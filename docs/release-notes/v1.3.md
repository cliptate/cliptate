# Cliptate v1.3

Release date: 2026-10-14 (Asia/Shanghai)
Previous version: [v1.2](https://github.com/cliptate/cliptate/releases/tag/v1.2)

## Highlights

A clearer light appearance, leaner downloads, and a simpler release-notes experience.

## Changes

- **Appearance:** Light-mode pages use a consistent light-gray canvas. Dark mode
  keeps its system background; localized screenshots and demo links are refreshed.
- **Downloads:** Release builds remove coverage instrumentation and strip shipping
  symbols before signing. DMGs use stronger compression, retaining license notices
  and the existing macOS minimum. Models remain separate downloads.
- **Compatibility:** Fixed source/test compiler warnings, clarified concurrency
  handling in CLI and model warmup, and retained App Store receipt-based update gating.
- **Release notes:** GitHub releases link to the website's five-language version
  details. Full repository notes remain embedded in Sparkle's in-app updates.
- **Development:** Make tasks run the existing CI and signed-package workflows
  locally through act. Local publication checks clean, pushed source before and
  after packaging. [Local Actions guide](https://github.com/cliptate/cliptate/blob/v1.3/docs/local-actions.md).

## Upgrade notes

- Requires Apple Silicon and macOS 15+. Update in the app, or close Cliptate and
  replace it using the DMG. Verify its SHA-256 file and restart before using the CLI.
- Settings, history, compatible model caches, and production app identity remain
  unchanged. No new migration is required. GitHub builds remain free; App Store
  subscription and capability rules remain unchanged.

## Known limitations

CLI transcription and speech generation still create no history entries. Nemotron
live dictation still uses the shared VAD pipeline. Real-model inference, microphone
input, and end-to-end update installation require manual validation.

## Validation

SwiftPM build, 775 tests, the direct-channel Release app build, 89 automation
tests, and dependency notices passed. Developer ID signing, notarization, and final
installer verification will run in the package workflow before publication.
Real-model, microphone, and end-to-end update checks were not manually performed.
