# Spokenly 对照审查：剩余页面与交互

日期：2026-10-16。基线：Cliptate `d18e0b9`。本轮仅审查，未修改产品源码。

方向：原生 macOS 语音工具，面向经常听写与处理媒体的用户；参考 Spokenly 的克制配色、分组列表和细项面板。ENERGY 1 / RHYTHM 1 / MOTION 1。保留 Usage 与 Dictation 默认展开，以及文件拖放区居中。

本轮实际操作了本机 Spokenly 和 Cliptate Dev，截图均为本轮新采集。Spokenly 为中文界面、约 1160 × 698 点；Cliptate 为英文浅色界面、1280 × 801 点。两者是结构与交互参照，不进行像素一致性打分。

## 结论与优先级

基础视觉已经统一。下一轮的主要收益来自状态准确性、就地反馈和操作分组，而非继续增加卡片或装饰。

### 1. HIGH：AI 增强的显示状态与实际可用状态脱节

证据：[设置](review-spokenly-2026-10-16/08-cliptate-settings.png)、[听写](review-spokenly-2026-10-16/09-cliptate-dictation.png)、[上下文面板](review-spokenly-2026-10-16/10-cliptate-context.png)。

全局 Enable AI Features 为关闭，Assistant 的 AI Enhance 仍显示开启，Clipboard and window 也显示已选择。静态核对 `VoiceToTextView.swift` 的 `startAssistantCommand` 和 `startDictationAutofix`：全局关闭时直接交付原始转录并退出，因此当前 UI 显示的是保存的偏好，不能代表这次会实际执行增强。

建议：保留用户偏好，同时显示独立的有效状态，例如“AI 功能未启用”，并提供“前往配置”。缺少密钥与全局关闭应分别说明；上下文摘要注明实际使用条件。不要用重置开关偏好的方式掩盖依赖关系。

规则：R-27 / C-2。理由：开启外观应让人准确预测下一次操作的结果。

### 2. HIGH：空文本生成的错误提示离输入框过远

证据：[提交前](review-spokenly-2026-10-16/11-cliptate-generation.png)、[提交后](review-spokenly-2026-10-16/12-cliptate-empty-validation.png)。

Script 为 0 chars 时主按钮仍可用。点击后虽然阻止了生成，但“Enter some text to synthesize.” 显示在声音设置之后，输入框自身没有就地反馈。

建议：空白文本时禁用生成并在按钮附近说明原因；需要提交校验时将提示放在 Script 内，焦点返回输入框。保留模型加载失败等不同错误的独立恢复动作。

规则：R-27。理由：用户应在出错的位置看到修复方法。

### 3. MEDIUM：历史详情的操作栏拥挤，显示选项缺少有效状态语义

证据：[列表](review-spokenly-2026-10-16/15-cliptate-history.png)、[详情](review-spokenly-2026-10-16/16-cliptate-history-detail.png)。

1280 点窗口下，“Open in File Transcription” 已被截断；打开、重新转录、Finder、复制、删除挤在同一行。样本没有译文与说话人信息，但 Translation 和 Speaker 仍显示蓝色开启，点击不会增加相应内容。AX 树仅暴露普通 button，没有报告四个显示选项的开关状态；`toggleChip` 源码也没有选中 trait 或 value。

建议：保留复制和打开作为主要动作，其余放入“更多”；根据可用数据显示选项，无数据时给出原因；为显示选项提供原生 Toggle 或明确 accessibilityValue。模型家族与完整模型名称可合并以减少重复。

规则：R-03 / R-26 / R-32。理由：动作必须可辨认，状态需要同时传达给视觉用户和辅助技术。

### 4. MEDIUM：转录编辑器与主界面的操作语言尚未统一

证据：[编辑器](review-spokenly-2026-10-16/17-cliptate-editor.png)、[导出](review-spokenly-2026-10-16/18-cliptate-export.png)。

编辑器保留较重的灰色配置列。Batch Actions 包含转录、增强、高亮、翻译和导出五个小图标；其中有全批次动作，也有仅作用于当前视频的动作。导出格式设置位于列的中部，执行导出却藏在顶部分享图标菜单，两处相距较远。

建议：显式区分“当前文件”和“全部文件”；主要任务使用文字按钮，低频动作进入菜单。导出页底部保留明确的“导出当前文件/全部文件”入口，并显示本次格式摘要。延续主界面的白色工作区和浅灰分组，不削弱字幕预览的对比。

规则：R-04 / R-20 / C-1。理由：用户应在执行前清楚动作的范围。

额外观察：恢复后两次捕获中预览有画面，但总时长显示 `--:--`、进度和跳转不可用。本轮未点击播放，无法判定媒体加载还是播放故障；下一轮应专项验证，并区分加载、文件不可用和可播放状态。

### 5. MEDIUM：模型页仍偏向技术清单，当前模型难以快速定位

证据：[VAD](review-spokenly-2026-10-16/13-cliptate-models.png)、[ASR](review-spokenly-2026-10-16/14-cliptate-asr.png)。参照：[Spokenly 模型](review-spokenly-2026-10-16/04-spokenly-models.png)。

首次进入显示 VAD，分类为 VAD / ASR / Align / TTS。ASR 列表按模型序列展示，当前 Qwen3 只在顶部摘要出现，其完整行需要向下找。VAD 活跃行的名称旁、右侧和列表摘要重复表达 Active。

建议：分类使用“语音识别 / 语音生成 / 语音检测 / 时间对齐”等易懂名称，技术缩写放次要位置。默认展示语音识别；从听写和生成页进入时直达对应分类并定位当前项。统一尺寸、语言、安装状态和操作列，压缩重复状态标签。用途说明只写可证实的能力，不照搬竞品的准确度评分。

规则：R-09 / R-20。理由：模型页应帮助选择与维护模型，而不是要求用户先理解推理管线。

### 6. LOW：设置页的低频维护项占据过多空间

证据：[Cliptate 设置](review-spokenly-2026-10-16/08-cliptate-settings.png)。参照：[Spokenly 分组](review-spokenly-2026-10-16/01-spokenly-settings.png)、[快捷键详情](review-spokenly-2026-10-16/02-spokenly-shortcuts.png)。

CLI 未安装时同时展示安装、卸载、PATH 和刷新四个同等权重按钮。更新状态与 AI 配置也直接展开在同一页。Dev 构建的 Launch at Login 禁用，但行内没有说明。

建议：将语言、外观、启动归为“通用”；AI 服务、命令行、更新用摘要行进入详情。CLI 根据安装状态只突出下一步动作。Dev 限制应就地解释，不能据此推断生产版也不可用。

规则：R-05 / R-15 / C-3。理由：常用偏好应容易扫描，维护细节按需展开。

### 7. LOW：词典空状态有说明，但编辑入口仍显得像空白画布

证据：[词典](review-spokenly-2026-10-16/19-cliptate-dictionary.png)。

左侧 Editor 完全空白，新增说明放在右侧 Active Entries。自动保存说明清楚，这是应保留的优点。

建议：在实际输入区域加入“每行输入一个词或短语”的占位提示，并让空状态提供“开始输入”的聚焦动作。右侧预览可在有词条时再强调；导入导出等新能力应另行确定需求，本轮不把功能缺失当成缺陷。

规则：R-20 / C-3。理由：说明与它所解释的输入位置应放在一起。

### 8. LOW：首页与文件入口还可以增强任务之间的衔接

证据：[首页](review-spokenly-2026-10-16/07-cliptate-home.png)、[文件入口](review-spokenly-2026-10-16/20-cliptate-file.png)。参照：[Spokenly 首页](review-spokenly-2026-10-16/21-spokenly-home.png)、[文件入口](review-spokenly-2026-10-16/05-spokenly-file.png)。

首页统计结构清楚，来源统计目前只是静态数字，可以作为跳转对应历史筛选的入口。累计听写、滚动十二个月活动和当前可查看历史的统计口径不同，现有保留期说明可以进一步就近表达。文件拖放已居中，但导入前看不到当前模型、语言和就绪状态。

建议：首页来源项连接相应历史筛选，补充最近记录入口时保持统计为主要内容；文件入口在拖放区下方增加一行模型、语言和“更改”摘要。目前选择器明确只允许 movie / video，因此应准确说明支持视频，不直接把音频扩展名加入文案；音频支持属于单独功能工作。

规则：R-20 / R-31。理由：统计与导入摘要应帮助用户进入下一项实际任务。

## 建议实施顺序

1. 修正 1、2 的有效状态与就地校验，再补 3 的可访问开关状态。
2. 重排 3、4 的操作优先级，专项检查编辑器播放状态。
3. 整理 5、6 的列表和详情层级。
4. 最后处理 7、8 的空状态和页面衔接。
