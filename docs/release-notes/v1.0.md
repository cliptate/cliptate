# Cliptate v1.0

Tag date: 2026-10-10 (Asia/Shanghai)
Source: `43ec063233cb32c972762c5eae389f42599ecd54`

This is the initial version release of the complete application in
`cliptate/cliptate`. These historical notes were reconstructed from the `v1.0`
tag and its development records; later CLI and app-lifecycle changes are outside
this version.

## Highlights

- The complete native macOS audio/video workspace is available as MIT-licensed
  source, including transcription, dictation, editing, translation, and speech
  synthesis.
- GitHub/direct-download builds unlock all models and Pro features without a
  subscription, purchase, or RevenueCat key. App Store builds retain their
  existing subscription policy.
- Direct-download builds include Sparkle updates, with a shared stable feed for
  both stable and Nightly installations.
- Existing compatible Hugging Face model snapshots can be reused from the shared
  cache rather than downloading another copy of the weights.

## Changes

### Audio and video workflows

- On-device file transcription supports the existing Parakeet, Qwen3 ASR, and
  FireRed engines. Custom vocabulary, model-aware language selection, alignment,
  and speaker attribution remain part of the transcription workflow.
- Voice dictation supports streaming recognition and configurable shortcuts.
  Direct builds enable the existing Accessibility-backed text-injection and
  shortcut capabilities when the required permission is granted.
- AI Cut includes pause trimming, speaker-labelled transcripts, correction,
  translation, and timeline editing. Existing FCPXML, SRT, ASS, and VTT exports
  are preserved.
- Speech synthesis retains preset voices, voice cloning, emotion control, and
  voice design. Speech models run locally; separately configured online AI
  providers may process correction or translation requests.
- The Models page centralizes model selection, downloads, preload, cache state,
  and retry controls. Alignment and TTS runtimes load on demand and participate
  in the existing idle cleanup policy.

### Distribution and updates

- Release installers use the fixed names `Cliptate.dmg` and
  `Cliptate.dmg.sha256`, with the application version stored in bundle metadata.
  The DMG includes an Applications shortcut and license notices.
- The package workflow requires Developer ID signing, Apple notarization,
  ticket stapling, and Gatekeeper verification before publication. The package's
  generated release information reports its actual signing status.
- Stable packages include a signed `appcast.xml` generated from the final DMG.
  The app menu, status item, and settings expose update checking. A missing
  initial feed is explained with a link to GitHub Releases.
- Nightly builds package `main` daily at 03:17 Beijing time, remain prereleases,
  and check the stable feed. Stable publication sets GitHub's Latest release.
- CI build numbers advance independently of the display version, allowing
  Sparkle to compare installations whose display version is still `1.0`.

### Source and compatibility fixes

- Both SwiftPM and Xcode use locked dependency graphs. MLX Swift/MLX Swift LM
  versions are pinned together to keep the selected MLX Audio implementation
  buildable across the supported toolchains.
- Model lookup understands Hugging Face snapshots and blob symlinks, and retains
  support for legacy MLX Audio cache directories. The selected model's repository
  identity must match its weights.
- Production bundle identity and the App Store Accessibility capability gate are
  retained. Local billing configuration is kept outside Git.

## Upgrade notes

- Requires an Apple Silicon Mac with macOS 15 or later. Model weights are
  downloaded separately; the first download requires internet access and enough
  local storage. Intel Macs are unsupported.
- Download `Cliptate.dmg`, verify it with `Cliptate.dmg.sha256`, open the image,
  and drag Cliptate into Applications. Close the previous app before replacing it.
  An installation without Sparkle requires this manual upgrade once.
- Automatic update checking uses Sparkle's consent prompt and preference. It
  does not enable automatic installation; Nightly also checks for stable updates.
- The v1.0 direct build remains sandboxed and adds access to
  `~/.cache/huggingface/hub` through its direct-distribution entitlements. Compatible
  snapshots are reused without copying weights. Cache overrides work only when
  accessible to this build.
- Existing application identity is preserved. This release does not introduce
  the later one-time sandbox-to-direct data migration. Keep the previous data
  and model caches when upgrading.
- Default source builds retain the App Store channel. Use `CLIPTATE_APP_STORE=NO`
  for the free direct channel. Source builds require Xcode 26+ and Swift 6.2+.

## Known limitations

- The native `cliptate` command-line helper is not included in the v1.0 tag.
- App Store builds retain their subscription and Accessibility restrictions.
  Public source builds have no embedded billing SDK key; App Store billing
  requires the developer's local configuration.
- Hardware/model tests require appropriate downloaded weights. Interactive UI
  smoke tests are opt-in; an interactive app launch was not validated.
- An unpublished stable update feed can return HTTP 404. The app explains the
  condition and links to manual downloads; it cannot install an update until a
  signed feed and installer have been published.

## Validation

No new test run of the tagged release was performed when reconstructing these notes.
Distribution signing and notarization are verified separately by the package
workflow. This historical document does not establish the status of an online
release asset or a completed end-to-end Sparkle update installation.
