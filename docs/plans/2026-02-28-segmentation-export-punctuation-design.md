# Segmentation + Export Punctuation Design (2026-02-28)

## Problem

Current segmentation/export behavior needs three aligned changes:

1. `SegmentSplitBySentence` should also support comma-based boundaries.
2. Whisper and Parakeet offline chunking/splitting should follow the same punctuation-driven idea currently used in Qwen3-related flow.
3. Add a switch to control whether export keeps punctuation; when disabled, exported SRT/FCPXML/burned-in video text should not contain punctuation.

Confirmed scope:

- Only offline transcription-to-export chain (AICut `SegmentProcess` + export path), not live `VoiceTranscriber` streaming.
- New export switch default: keep punctuation (backward compatible).
- Punctuation removal applies to both original text and translation text.

## Options Considered

### A) Shared rules + centralized export text normalization (**Chosen**)

- Build shared segmentation rule helpers for punctuation boundaries.
- Reuse them across `SegmentSplitBySentence`, Whisper offline segmentation, and Parakeet offline segmentation.
- Normalize text once in export preparation so SRT/FCPXML/ASS(burn-in) stay consistent.

Pros: single source of truth, low drift risk, consistent outputs.  
Cons: touches multiple services and config/preset wiring.

### B) Per-engine and per-exporter custom changes

Pros: local edits per file.  
Cons: duplicated logic, easy to drift, harder maintenance.

### C) Late string replace only at file write time

Pros: fastest patch.  
Cons: high risk for style/highlight/text layout mismatch and inconsistent behavior.

## Architecture

### 1) Shared segmentation rule layer

Add a small shared rule helper (e.g. `SegmentationRules`) to define punctuation boundary checks, including comma variants:

- Sentence-ending punctuation (existing)
- Comma punctuation (`,` `，` `、` etc., exact set finalized in code constants)

This helper is consumed by:

- `SegmentSplitBySentence`
- Whisper offline segmentation/chunk split path
- Parakeet offline segmentation/chunk split path

### 2) Export punctuation normalization layer

Add a text normalization helper for export-only text (e.g. `ExportTextNormalizer`) with:

- `keepPunctuation: Bool`
- normalization for original and translation text
- punctuation stripping while preserving spacing/readability

### 3) Export config surface

Add `keepPunctuationOnExport: Bool` into:

- `AppConfiguration`
- `ConfigPresetStore.ConfigPreset.Payload`
- Export UI (`ControlPanelConfigurationView` output section)

Default is `true`.

## Data Flow

1. Base transcript segments generated by transcriber.
2. `paddedSegments(for:)` applies existing operations (`splitBySilence` / `splitBySentence` / char split / padding).
3. Shared punctuation rules apply during offline splitting paths.
4. At export preparation (`buildMediaFiles` / export entry), derive export-ready media text using `keepPunctuationOnExport`.
5. Exporters consume normalized media:
   - `SubtitleFileExporter` (SRT/ASS/TXT)
   - `FCPXMLExporter`
   - `VideoExporter` via ASS rendering pipeline

Raw in-memory editing text remains unchanged.

## Error Handling & Compatibility

- No broad silent fallback additions.
- If punctuation stripping yields empty text, existing empty-segment filtering behavior remains the guard.
- Backward compatibility: default keep punctuation keeps current output unchanged.

## Testing Plan

1. **Segmentation unit tests**
   - `SegmentSplitBySentence` splits at commas as expected.
2. **Rule consistency tests**
   - Whisper/Parakeet offline segmentation boundaries align with shared punctuation rule behavior.
3. **Export behavior tests**
   - `keepPunctuationOnExport = true`: baseline unchanged.
   - `keepPunctuationOnExport = false`: SRT/FCPXML/ASS outputs remove punctuation in both original and translation text.

## Out of Scope

- Real-time `VoiceTranscriber` streaming segmentation behavior.
- Changing punctuation behavior for on-screen editing text outside export context.
