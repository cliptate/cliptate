# Cliptate v1.1

Release date: 2026-10-12 (Asia/Shanghai)
Previous version: [v1.0](https://github.com/cliptate/cliptate/releases/tag/v1.0)

## Highlights

- The direct-download app now includes a native `cliptate` command-line helper
  for batch audio/video transcription and custom dictionary management. Scripts
  and AI agents can use structured JSON results and subtitle exports.
- Dictation reports missing microphone input, silent input, and recognition
  failures, with guidance for checking the current input device.
- Stopping dictation retains trailing speech and saves available live text when
  the final transcription fails or returns no text.
- Login-item settings perform system queries off the UI thread and Swift's
  cooperative worker pool, improving responsiveness during startup and settings use.

## Changes

### Command-line transcription and dictionary

- Install the bundled helper from Settings → Command Line into `~/.local/bin`
  without administrator privileges. Existing commands are never overwritten.
- Transcribe one or more local audio/video files as text, JSON, Markdown, SRT,
  or VTT. Model and language overrides apply to the request without changing
  saved application settings; `--download` explicitly permits missing model downloads.
- Batch jobs report per-file errors and continue with later inputs. Progress
  and diagnostics go to stderr. Output files require `--overwrite` before
  replacing existing files; input files cannot be overwritten.
- List, add, remove, import, and export recognition vocabulary. Dictionary
  mutations are persisted before success is returned and update the open editor.
- The helper starts the app in the background when necessary and shares its
  configuration and model runtime. Authenticated local requests handle cancellation
  and connection failures; mutations are not retried after authentication.
- Expanded `--help` documents JSON fields, output rules, exit codes, environment
  variables, and scripting examples. See the
  [CLI guide](https://github.com/cliptate/cliptate/blob/v1.1/docs/cli.md).

### Dictation and application lifecycle

- Microphone diagnostics appear in the dictation view and floating indicator,
  including a shortcut to Sound settings for missing or silent input.
- Audio tap samples are copied before asynchronous processing, and capture
  uses a compatible Float32 format. Final buffered audio and trailing VAD speech
  are drained when stopping instead of being omitted from the final result.
- Available streaming transcripts are saved to history as a fallback when
  final recognition fails. A failed dictation remains visible briefly in the
  floating indicator so its diagnostic can be read.
- Added login-at-startup settings that report the actual system registration
  state and registration errors. Serial background IPC preserves operation order
  without blocking the main actor or cooperative worker pool.
- Background CLI launches avoid opening the main window. Opening the UI can
  preserve the user's lightweight startup preference.

### Distribution and inference compatibility

- Direct-download builds now run without App Sandbox and reuse the account's
  real Hugging Face cache. Missing configuration, presets, and transcript history
  are copied once from the previous sandbox container without deleting originals
  or replacing existing direct-build data.
- Updated and pinned the inference dependency graph to MLX Audio Swift 0.1.5,
  MLX Swift 0.32.3, and MLX Swift LM 3.32.3, with compatible model-download,
  diarization, and TTS reference-audio handling.
- Release signing removes debugging entitlements from the embedded CLI.
  Notarization failures include Apple's rejection details in build logs.
- Version releases now use a committed, detailed release document for both
  GitHub Release and Sparkle. Nightly remains a rolling prerelease and follows
  the stable update feed. README screenshots are available in each supported language.

## Upgrade notes

- Requires Apple Silicon and macOS 15 or later. Model weights remain separate
  downloads; compatible existing Hugging Face snapshots can be reused.
- Update through the app's Sparkle updater, or download `Cliptate.dmg` and its
  SHA-256 checksum from this release. Close Cliptate, verify the checksum, and
  drag the app into Applications to replace the previous version.
- The production bundle identifier is unchanged. Keep the previous sandbox
  data when upgrading: the direct app copies missing data on first launch and
  leaves the source intact. macOS can still request access to privacy-protected
  files or devices; grant the permissions needed for your workflow.
- Move the app to its final location before installing the CLI symlink and add
  `~/.local/bin` to `PATH`. Restart the app after upgrading before using the new helper.
- App Store builds retain their sandbox, subscription policy, and Accessibility
  restrictions; they do not include the CLI. Source builds retain the App Store
  channel by default. Use `CLIPTATE_APP_STORE=NO` to build the free direct channel.

## Known limitations

- The CLI accepts local file paths, not stdin audio. It shares the application's
  mono audio pipeline and allows one CLI transcription at a time. It does not
  create projects or transcript-history entries.
- JSON batch output is emitted after processing finishes. Check both the exit
  status and each `files[].error`; a failed batch can still contain successful
  results. An interrupted batch includes completed inputs and omits the cancelled input.
- Recognition quality and inference speed depend on the selected model, language,
  audio, available memory, and hardware. Model downloads require internet access.
- Hardware/model inference, interactive microphone use, login-item approval,
  and end-to-end Sparkle installation require separate manual verification.
  Public App Store source builds require local billing configuration for purchases.
